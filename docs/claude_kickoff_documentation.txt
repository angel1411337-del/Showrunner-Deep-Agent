## **1. RLM (Recursive Language Models)** - The Big One
**Paper**: arXiv:2512.24601 (Alex Zhang, MIT - December 2025)

This is exactly what you described wanting. Instead of cramming 1.7M words into context:
- Prompt becomes a **Python variable in a REPL**
- Model writes code to slice, search, query the text
- Launches **sub-LLM calls** on specific snippets
- Handles inputs **100x beyond** native context windows
- **Comparable cost** to single model calls

**For ASOIAF**: Query "every prophecy mentioning dragons," get exact passages, cross-reference with character chapters, all programmatically. No forgetting.

## **2. GraphRAG 2.0 Ecosystem**

The field has matured massively since you started your Halo GraphRAG:

**Key advances:**
- **FalkorDB GraphRAG SDK**: 90% hallucination reduction, sub-50ms queries [Medium](https://medium.com/@claudiubranzan/from-llms-to-knowledge-graphs-building-production-ready-graph-systems-in-2025-2b4aff1ec99a)
- **Cognee**: Cognitive memory layer combining graph structures with vector embeddings - specifically for agents that need to reason across sessions [Medium](https://medium.com/@claudiubranzan/from-llms-to-knowledge-graphs-building-production-ready-graph-systems-in-2025-2b4aff1ec99a)
- **LightRAG**: 10x token reduction vs Microsoft GraphRAG, 65-80% cost savings
- **GFM-RAG** (NeurIPS 2025): Graph Foundation Model for retrieval

**For ASOIAF**: Build the relationship graph (houses, allegiances, debts, prophecies), then query across it with natural language. "Who owes the Lannisters money and has reason to betray them?"

## **3. Zep: Temporal Knowledge Graphs for Agent Memory**

This architecture incorporates semantic and episodic memory alongside entity and community summaries, achieving state-of-the-art on memory benchmarks while reducing token costs. [Getzep](https://blog.getzep.com/content/files/2025/01/ZEP__USING_KNOWLEDGE_GRAPHS_TO_POWER_LLM_AGENT_MEMORY_2025011700.pdf)

**Key innovation**: Tracks when relationships *changed* over time (critical for ASOIAF where alliances shift constantly). Uses label propagation for community detection.

**For ASOIAF**: "Who was allied with the Starks before the Red Wedding vs after?" becomes a queryable timeline.

## **4. Mind Map Agent (Agentic Reasoning)**

From the February 2025 paper on deep research:

The Mind Map agent constructs a structured knowledge graph to track logical relationships, improving deductive reasoning. During reasoning, the model proactively embeds specialized tokens (web-search token, coding token, mind-map calling token) to interact with external agents. [arXiv](https://arxiv.org/html/2502.04644v1)

**For ASOIAF**: As the model reasons about plot resolution, it builds a visible map of what it's tracking - which prophecies need resolution, which Chekhov's guns remain unfired.

## **5. Multi-Agent Debate (With Caveats)**

The research got more nuanced in 2025-2026:

Multi-Agent Debate: Majority Voting alone accounts for most of the performance gains typically attributed to MAD. Debate induces a martingale over agents' belief trajectories, meaning debate alone does not improve expected correctness. [OpenReview](https://openreview.net/forum?id=iUjGNJzrF1)

**But**: Adaptive Heterogeneous Multi-Agent Debate (A-HMAD) uses diverse specialized agents and dynamic debate coordination. Achieves 4-6% accuracy gains and reduces factual errors by over 30%. [Springer](https://link.springer.com/article/10.1007/s44443-025-00353-3)

**For ASOIAF**: Don't use homogeneous agents all debating the same way. Use:
- Lore Expert agent (trained on wiki/supplementary material)
- Prophecy Interpreter agent
- Character Psychology agent  
- Plot Structure agent
- Foreshadowing Tracker agent

Have them debate with assigned expertise, not generic "what do you think?"

## **6. Character Generalization & Roleplay Fine-tuning**

**RoleplayLLM framework** (NLPCC 2025):
Uses two-stage training—Supervised Fine-Tuning (SFT) for foundational alignment, followed by Direct Preference Optimization (DPO) to refine response quality according to human preferences. Outperforms GPT-3.5 on both real and fictional characters. [Springer](https://link.springer.com/chapter/10.1007/978-981-95-3349-7_4)

**OpenCharacter** (September 2025):
- Character Generalization - models that adapt to *arbitrary* user-defined characters
- Trained on large-scale synthetic personas
- Two strategies: response rewriting and direct generation

**For ASOIAF**: Fine-tune separate character voice models on their POV chapters. Tyrion-voice, Jon-voice, Daenerys-voice. Then the agentic system chooses which voice to deploy for which chapter continuation.

## **7. CollabStory: Multi-LLM Collaborative Story Generation**

This study focuses on long-form stories in various genres written by either single agents or up to 5 agents. Each agent writes a segment of the story and passes it to the next agent to add their own part, and the process continues until a coherent narrative is produced. [ACL Anthology](https://aclanthology.org/2025.findings-emnlp.750.pdf)

**For ASOIAF**: Instead of one model writing everything, have specialized agents hand off:
- Plot architecture agent sets the outline
- Character voice agents write individual POVs
- Continuity agent checks for contradictions
- Foreshadowing agent ensures setup/payoff

These architectures let agents:

A lot of LLM benchmark and performance progress will come from improved tooling and inference-time scaling rather than from training or the core model itself. **For ASOIAF**: Instead of generating once, have the system:

### **1. CAUSAL WORLD MODELS FOR NARRATIVE REASONING**

**"Language Agents Meet Causality" (ICLR 2025)**
- Framework that integrates Causal Representation Learning (CRL) with LLMs
- Learns a causal world model with variables linked to natural language expressions
- The causal world model acts as a simulator the LLM can query and interact with
- **Outperforms standard LLM reasoners, especially for longer planning horizons**

**FOR ASOIAF:** Build a causal model of the story world—if character X does Y, what consequences cascade? Track "if Robb had married a Frey" counterfactuals. Map cause→effect chains for prophecy fulfillment paths.

### **2. DIFFUSION LANGUAGE MODELS (DLMs)**

**Google Gemini Diffusion (I/O 2025)**
- First commercial-grade DLM achieving parity with autoregressive models
- **1,479 tokens per second**—5x faster than comparable AR models
- Enables controllable generation via gradient-based methods
- SEDD (ICML 2024 Best Paper): 6-8× better perplexity than GPT-2 with 32× fewer network evaluations

**LLaDA (2025)**
- Masked diffusion model trained from scratch challenging autoregressive dominance
- Demonstrates scalability and competitive results vs LLaMA3

**FOR ASOIAF:** Non-autoregressive generation could enable better global coherence across chapters. Control attributes like tone, pacing, tension level through continuous diffusion steering rather than rigid prompting.

### **3. HALLUCINATION DETECTION & CORRECTION SYSTEMS**

**SUScore + ICQ Framework (NLPCC 2025)**
- Substantive-word Uncertainty Score: Quantifies uncertainty over semantically important tokens (nouns, verbs, numerals)
- Iterative Chain-Query (ICQ): Multi-step consistency checking with optional RAG enhancement
- Model-agnostic, requires no retraining

**HaluGate (vLLM, December 2025)**
- Production-ready token-level hallucination detection
- 76-162ms overhead—negligible compared to generation times
- Three-stage pipeline: Prompt classification → Token detection → NLI explanation

**FINCH-ZK (EMNLP 2025)**
- Zero-knowledge hallucination detection through cross-model consistency
- Block-level correction with iterative refinement
- Works without external knowledge bases

**FOR ASOIAF:** Critical for ensuring generated content doesn't contradict established lore. Run every generated passage through SUScore to flag uncertain claims, then ICQ to verify against the GraphRAG knowledge base.

### **4. DOME: DYNAMIC HIERARCHICAL OUTLINING WITH MEMORY-ENHANCEMENT (NAACL 2025)**

- Combines novel-writing theory with plan-write framework
- **Temporal Knowledge Graph (TKG)** stores generated story and tracks relationship evolution
- **87.61% conflict reduction** through memory-enhancement module
- Dynamic outline expansion adapts to uncertainty during generation

**How It Works:**
1. Rough outline generated for story stage
2. Each outline expanded into detailed outlines based on TKG queries
3. Partial stories generated, stored in TKG
4. Semantic filtering keeps historical information concise

**FOR ASOIAF:** Perfect for managing the five-book handoff. Each book's major plot points become outline stages, with the TKG tracking every character relationship, alliance, and debt across all generated content.

### **5. SPECULATIVE DECODING MATURATION**

**EAGLE-3 (NVIDIA 2025)**
- Lightweight autoregressive prediction head attached to target model
- Eliminates need for separate draft model
- **3.6× throughput improvements** on H200 GPUs

**Heterogeneous Vocabulary Speculative Decoding (Intel/Weizmann, ICML 2025)**
- Any draft model can accelerate any target model regardless of vocabulary
- **2.8× speedup** with off-the-shelf models, no retraining
- Already integrated into Hugging Face Transformers

**FOR ASOIAF:** Massive generation project benefits enormously from 2-3× speedup. Use small fine-tuned GRRM-voice draft model to propose tokens, verified by larger reasoning model.

**CogWriter**

### **7. CONTEXT CACHING FOR MASSIVE CORPORA**

**Strata: Hierarchical Context Caching (August 2025)**
- Up to **3.75× improvement** in time-to-first-token on long-context workloads

- Exploits GPU, CPU, DRAM, SSD hierarchy

**Epic: Position-Independent Context Caching**
- **7× throughput improvement** vs existing systems
- AttnLink algorithm leverages static attention sparsity
- KVSplit customizable chunking strategy
- Works even when token order differs across requests

**FOR ASOIAF:** The 1.7M word corpus would benefit enormously from caching. When generating Chapter X, the KV cache from previous chapters remains available without recomputation. Position-independent caching allows querying any part of the corpus without prefix matching.

# PRD-Lite (Locked) — Showrunner Orchestrator (MVP → V1) — **Tooling Updated (Feb 2026)**

## 1) Product Summary

A contract-driven deep orchestrator agent on a **Deep Agents harness** (planning + filesystem + subagents) and a **LangGraph v1** stage DAG runtime that:

* Ingests a long narrative corpus as stable, evidence-addressable passages
* Builds a living canon substrate (entities, obligations, state) with provenance
* Produces writer-ready planning docs (dossier first; then master outline, reveal ledger, twist bank)
* Supports passive, incremental structuring via git hooks
* Supports non-linear drafting (beginning/middle/end) and world-first sci-fi later in V1+

North Star: series-scale continuity and planning without hallucinated canon, with progressive enforcement.

## 14) Core loops (what must run to be “real”)

### 14.1 The Run Spine Loop (non-skippable)

**plan → execute → verify → export → checkpoint**

* **Plan:** staged TODO locked to pipeline stages
* **Execute:** stage DAG runs deterministically
* **Verify:** gates must pass (schemas, evidence, invariants)
* **Export:** renders only from validated stores
* **Checkpoint:** saves resumable state + manifests

### 14.2 Data construction loops (always necessary)

* **Index loop:** corpus → passages/index → evidence anchors
* **ER loop:** mentions → candidates → link → overrides → entities
* **Obligations loop (ASOIAF):** extract → evidence → merge → status → ledger
* **World loop (SF):** worldspec → patch → validate → commit

### 14.3 Repair loop (always necessary)

**fail gate → diagnose → propose fix → apply patch → re-verify**

* repairs are recorded as patches, not silent edits

### 14.4 Authoring loop (SF final target)

**outline → scene draft → constraint check → state update → export**

* each unit updates `world_state` and preserves continuity

---

## 15) Protections & gates (non-negotiable correctness posture)

### 15.1 Non-skippable gates (hardwired)

1. **Run Manifest Gate**

* no run without `run_manifest.json` (input hashes, model IDs, prompt hashes, tool versions)

2. **Evidence Gate (ASOIAF)**

* no obligation or canon claim without ≥1 evidence anchor pointing into `canon/passages.jsonl`

3. **Schema Gate**

* all outputs validate (entities, obligations, state, worldspec)

4. **Referential Integrity Gate**

* every `entity_id`, `passage_id`, and edge reference resolves

5. **Baseline Invariant Gate**

* dead-but-acting, impossible location overlap, timeline contradictions (cheap checks)

6. **Export Gate**

* exports render only from validated stores (no “LLM wrote the dossier directly”)

7. **Audit Gate**

* `audit/tool_calls.jsonl` exists and matches run_id

### 15.2 Optional gates (skippable by user only)

* full contradiction sweep (expensive)
* heavy belief-state legality checks (deep)
* cross-model factuality checks
* large golden-eval suite (release-only)

---

## 16) User-only skip policy (skip optional work safely)

### 16.1 Policy-as-code

* `run_policy.yaml` defines:

  * required stages (non-skippable)
  * optional stages (skippable)
  * budgets per stage
  * dev vs release mode

### 16.2 User-only skip mechanism (MVP)

**Interactive approval interrupts**

* when an optional stage is next:

  * system pauses and presents:

    * cost estimate
    * expected value
    * risk of skipping
* only the user can approve “skip” or “run”
* decision is logged to `policy_decisions.json`

### 16.3 User-only skip mechanism (production hardening)

**Signed override file**

* `overrides/skip.json` includes:

  * run_id, stages_to_skip, reason, timestamp
* signed by user key
* pipeline verifies signature before skipping

### 16.4 “Break-glass” limitations

* you can skip optional stages
* you cannot skip non-skippable gates
* you cannot disable audit/provenance

## 17) Harness hooks (how enforcement is implemented)

### 17.1 Supervisor hooks (Deep Agents harness)

**Enforce**

* plan must exist and match known stage DAG
* filesystem working memory: artifacts must be written to disk
* tool allowlist: agent cannot bypass gates with unauthorized operations

### 17.2 Graph hooks (LangGraph execution)

**Enforce**

* stage entry: prerequisite checks
* stage exit: artifact contract + schema gate + metrics gate
* checkpoint after each stage
* interrupts for user approval and high-severity findings
* repair node routing when gates fail

### 17.3 Runtime hooks (LangChain callbacks)

**Enforce**

* tool policy firewall (paths, tools, budgets)
* audit log append on every tool call
* retry limits and error classification
* completion checks (required artifacts exist)
